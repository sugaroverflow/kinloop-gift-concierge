# Kinloop Design Brief

## Register

product

## Visual Direction

Kinloop should feel like a polished relationship command surface for a consumer app: bright, fast, slightly electric, and still easy to trust. The UI should prioritize the next useful decision, not the implementation machinery.

## Scene

The user checks Kinloop on a laptop in the morning before work, with a phone nearby and only a few minutes to decide whether a birthday gift is on track. The interface should be light, crisp, and direct.

## Palette

- Use OKLCH colors.
- Use tinted pearl and graphite neutrals with a vivid green accent and small coral highlights.
- Avoid ecommerce blue/yellow/red, beige-heavy palettes, purple-heavy gradients, and dark dashboard cliches.
- Use color for progress, selection, approval, and reminder state.

## Typography

- Use a system UI stack.
- Keep type fixed and product-appropriate.
- Labels and data should be crisp, compact, and highly readable.
- Avoid oversized marketing type inside the app surface.

## Layout

- First viewport should show source state, priority birthday, people, and gift reveal.
- Keep internal integrations out of the visible workflow.
- No nested cards.
- No landing-page hero.
- No marketplace nav, cart, saved-list, or merchant-handoff affordances.

## Components

- Stable dimensions for people rows, option cards, controls, and status chips.
- Clear loading, error, empty, ready, approved, and reminder-enabled states.
- Buttons should use consistent vocabulary and should not resize when labels change.
- Privacy and controls belong in quiet footer or settings copy, not as a central workflow.

## Motion

- Use motion only for import, reveal, approval, and reminder feedback.
- Keep transitions in the 150-220ms range.

## Imagery

- Use generated/static character styling when available.
- Do not depend on remote stock imagery as the visual identity.
